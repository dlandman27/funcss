# AdSense on the main page — design

**Date:** 2026-10-04
**Status:** Approved, implementing

## Goal

Monetize randomsitesontheweb.com with Google AdSense, placed only on the main
directory page: between some category sections and once at the bottom. The 100+
individual toy pages stay ad-free and immersive.

Publisher ID (live): `ca-pub-1505383837343849`.

## Constraints & context

- The main page `index.html` is **generated** by `scripts/build.js` from
  `templates/home.html` + `catalog.json`. Never hand-edit `index.html`; it is
  overwritten on every build. All source edits go in the template and build script.
- `scripts/build.js` `renderSections()` emits, per `catalog.sections` entry, a
  `<h2 class="category-title {key}">` followed by `<div class="site-grid">…cards…</div>`.
  There are 7 sections.
- The existing search/filter logic (`filterCards()` in the template) hides
  `#featured` and empty category grids while the user searches or filters. Ad
  slots must hide the same way, or an ad floats in the middle of filtered results.
- `sortCards()` reorders cards *within* each `.site-grid`; ad slots live *between*
  grids, so sorting leaves them untouched.
- Two milestones, not conflated:
  1. **Verify ownership** (what AdSense is asking for now) — satisfied by `ads.txt`
     (whole-domain) and/or the loader `<script>` in `<head>`.
  2. **Serving ads** — happens only after AdSense reviews/approves the site, and
     per-slot ad-unit IDs must be created in the AdSense dashboard first.

## Design

### 1. `ads.txt` (new static file, repo root)

```
google.com, pub-1505383837343849, DIRECT, f08c47fec0942fa0
```

Served statically from root by both Vercel (`outputDirectory: "."`) and the local
Express app (`express.static(__dirname)`). Not generated by the build, so a plain
checked-in file is safe. Satisfies AdSense's `ads.txt` verification and is required
for serving regardless.

### 2. Loader script in `<head>` (`templates/home.html`)

```html
<script async src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-1505383837343849"
     crossorigin="anonymous"></script>
```

Added once, near the existing analytics tags. Present on the home page only (that
is the only page that serves ads). Needed for AdSense's "code snippet" verification
and for the site review. Loading it while no ad is pushed is harmless.

### 3. Ad-slot component (`templates/home.html` CSS + markup)

CSS, hidden by default so the live site is unchanged until we flip it on:

```css
.ad-slot { display: none; }
.ad-slot.is-active {
  display: block;
  max-width: 1120px;      /* match .directory-inner */
  margin: 40px auto;
  padding: 8px;
  text-align: center;
}
.ad-slot__label {
  display: block;
  font: 600 11px/1 var(--font-display, sans-serif);
  letter-spacing: .12em;
  text-transform: uppercase;
  opacity: .45;
  margin-bottom: 8px;
}
.ad-slot ins.adsbygoogle { display: block; min-height: 90px; }
```

Each slot's markup (one `data-ad-slot` to fill per unit, post-approval):

```html
<div class="ad-slot" data-ad-name="home-inline-1">
  <span class="ad-slot__label">Advertisement</span>
  <ins class="adsbygoogle" style="display:block"
       data-ad-client="ca-pub-1505383837343849"
       data-ad-slot=""
       data-ad-format="auto"
       data-full-width-responsive="true"></ins>
</div>
```

### 4. Placement (3 slots)

- **Between sections:** `renderSections()` in `scripts/build.js` injects a slot
  after the 3rd and 5th section (0-based index 2 and 4). `data-ad-name`
  `home-inline-1` / `home-inline-2`.
- **Bottom of page:** one slot placed directly in `templates/home.html` right after
  `{{SECTIONS}}`, before the "And more to come…" footer. `data-ad-name`
  `home-bottom`.

Three units on a long 100-card scroll keeps content the primary focus (AdSense
policy) while covering top, middle, and end of the page.

### 5. Activation flags (`templates/home.html` inline script)

```js
const ADSENSE_CLIENT = 'ca-pub-1505383837343849';
const ADS_LIVE = false; // flip true after approval + filling every data-ad-slot ID

function initAds() {
  if (!ADSENSE_CLIENT || !ADS_LIVE) return;         // slots stay hidden
  document.querySelectorAll('.ad-slot').forEach(slot => {
    const ins = slot.querySelector('ins.adsbygoogle');
    if (!ins || !ins.getAttribute('data-ad-slot')) return; // no unit id yet
    slot.classList.add('is-active');
    try { (window.adsbygoogle = window.adsbygoogle || []).push({}); } catch (e) {}
  });
}
```

Called once after the existing event-listener setup. While `ADS_LIVE` is false,
slots render nothing and are `display:none`, so the loader script can sit live for
verification/review without showing empty boxes.

### 6. Hide during search/filter

In `filterCards()`, reuse the already-computed `filtering` condition and hide
active ad slots alongside `#featured`:

```js
document.querySelectorAll('.ad-slot.is-active').forEach(s => {
  s.style.display = filtering ? 'none' : '';
});
```

(`filtering` is currently scoped inside the `#featured` block; lift it so both uses
see it.)

## Out of scope / notes

- Toy pages: untouched.
- **Bot-traffic hardening** (the Aug 2026 Vercel overage) should land before
  `ADS_LIVE` is flipped true — AdSense bans accounts for invalid traffic. Not
  implemented here; flagged as a prerequisite to going live.

## Go-live checklist (after this ships)

1. Deploy. Then click "I've placed the code" in AdSense to verify ownership.
2. Wait for AdSense site approval.
3. Create 3 ad units in the AdSense dashboard; paste each `data-ad-slot` ID into
   the three slots.
4. Set `ADS_LIVE = true`, rebuild, deploy.
